# グランドサルーン 4.3

運営専用車両 `rolls-royce-operator`（珀樹 グランドサルーン）に、ユーザー提供の `luxury_car_under_25MB.glb` を使用します。ゲーム内の運営解放方法と車両IDは維持します。

## モデルの扱い

- 24,970,372バイトのGLBを変更せず収録。SHA-256: `730254e6e74205c927bb2da14abe97419406df5ea09bc4e284eabec71e3743cd`。
- 344,326頂点・551,070三角形、元のUV/法線とPBRテクスチャを読み込みます。
- 車長5.419mに均等拡縮し、中心と接地位置を調整。前後の反転や車体形状の削減は行いません。
- 元の外観を保つため塗装・傷の見た目による上書きを行いません。性能と整備の計算は従来のものです。
- 元GLBは単一メッシュで、タイヤ・ドアの独立したアニメーションを含みません。

## 表示と読み込み

通常のWebGL表示は3Dモデルと元テクスチャを使用します。GPUを使えない互換描画は、同じモデルをBlender CPUで描画した24方向の透過画像を使用します。互換画像は角度ごとの事前描画で、任意視点の3D描画とは異なります。

対象車両を必要とするときに読み込みます。実際の受信量に基づく進捗、中止・再試行、タイムアウト、車両切替中の遅延応答を扱います。元モデルをロードできない間は簡易車体となり、状態を表示します。レース準備中も読み込みを中止して戻れます。

テクスチャはページ内で共有し、レース終了では車両インスタンスの形状・材質だけを解放。互換画像の展開済みキャッシュは6方向に制限します。

## 検証と配布

`npm run test:saloon` は元ファイルの完全一致、全形状/材質、実ゲームの車体生成・解放・再作成、対象車両限定の置換、読み込み中止/再試行、UI状態、24方向の画像枠を確認します。既存の `npm test` で全車両・走行・経済・保存・サイト構造も検証します。

実ゲームの互換描画をCPUで実行し、1440×810と390×844で車両の向き・接地・表示枠を確認しました。

この環境ではブラウザ操作ツールを利用できません。元モデルの見た目はBlender CPUで確認しましたが、実ブラウザWebGL・実スマートフォンのFPS/操作・複数実機対戦は未確認です。

GitHubへ転送した一時データはSHA-256確認後に作業ブランチで復元し、削除します。全テストと公開用生成が成功してから、通常の自動main統合とGitHub Pages公開を起動します。今回の差分配布基準は4.2の `45f245c6d7051b589e03710dfcdc47d8ec83817c` です。
